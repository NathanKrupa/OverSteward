## cost-tier-ladder

**Kind:** operator-loop · **Status:** active

Advisory norm — pick the cheapest capable tier for triage/classification/routing, escalate on a defined per-rung failure signal.

**When to use:** Choosing which engine handles a triage, classification, or routing task — reach for this before defaulting to a frontier model.

| Phase | Detail | Model |
| --- | --- | --- |
| Try cheapest capable rung | Start at the lowest rung that could plausibly do the task (deterministic Python where the rule is expressible in code). | — |
| Escalate on failure signal | On the rung's defined failure signal (see table), climb one rung and retry — never skip straight to the top. | — |
| Retrospective dream-cycle audit | Dream cycle flags "ran on Opus, could've run cheaper" from the transcript record; not a runtime gate. | opus |

## What this is (and is not)

A **written norm**, not a runtime router. Nothing here intercepts a call and
downgrades the model at execution time. The ladder makes "cheapest capable tier"
a rule the operator applies by hand and the **dream cycle audits retrospectively**
("ran on Opus, could've run cheaper") — replacing the per-task judgment call that
the sovereignty quiz dinged. There is no code path that enforces it; treat a
violation as a smell surfaced after the fact, not a blocked action.

## Scope

This applies to **triage, classification, and routing** — the places where cheap
tiers actually bite and a wrong answer is cheap to catch and retry.

It does **NOT** apply to PR-coding dispatch. `<repo>-dev` build-to-merge agents
realistically stay on frontier models; the ladder is not an invitation to run
code generation on Haiku. Do not read "cheapest capable tier" as "all dispatch
can ladder down."

## The ladder

Climb only as far as the task demands. Each rung names the signal that means
"this rung failed — escalate."

| Rung | Tier | Use when | Failure signal → escalate |
| --- | --- | --- | --- |
| 1 | Deterministic Python | The decision is expressible as a rule (regex, lookup table, threshold, schema check) | Rule can't be written, or hand-audit shows it misses cases it must catch |
| 2 | Local-GPU model (qwen2.5:7b, RTX 4060) | Fuzzy classification with a tolerant, retriable consumer; a cheap wrong answer is recoverable | Low agreement vs a reference sample, refusal/format break, or confidence below the task's floor |
| 3 | Haiku | Local model can't hold the task but it's still light triage/labeling | Malformed structured output, obvious misclassification on a spot-check, or task needs reasoning it can't sustain |
| 4 | Sonnet | Judgment/nuance beyond Haiku (the current default for most classification) | Reasoning gap on the actual task — misses context a stronger model would hold |
| 5 | Opus | Genuinely hard reasoning, adversarial verification, or the retrospective audit itself | — (top rung) |

## Escalation mechanism

The ladder is **try-cheap → escalate-on-failure**, one rung at a time:

1. Start at the lowest rung that could plausibly do the task.
2. Run it. Check the rung's **failure signal** (the table's right column).
3. **No failure signal → done.** The cheapest capable tier handled it.
4. **Failure signal fires → climb exactly one rung and retry.** Do not skip to
   the top "to be safe" — skipping is the judgment call this norm exists to remove.
5. The dream cycle reads the transcript record and flags cases that ran higher
   than the failure signals justified.

The per-rung failure signal is what makes this a mechanism and not just a list:
without a defined "this rung failed" test, "cheapest capable tier" collapses back
into per-task guesswork.

## Enforcement is advisory + retrospective

- **Advisory at the point of use:** the operator consults this table; nothing
  blocks a too-expensive choice in the moment.
- **Retrospective via the dream cycle:** the dream cycle audits transcripts for
  "could've run cheaper" and flags them (`data/dream/flagged.jsonl`).
- Flagged over-spend is a norm violation to learn from, not an incident.

## Measurement is not built here

Honest cost reconciliation — "what actually ran on which tier, and what did it
cost" — depends on the **dispatch telemetry ledger (OS#96, still open)**. Until
that owned, structured dispatch record exists, the audit half of this ladder runs
on transcript inspection alone: it can flag an obvious "ran on Opus, could've run
cheaper," but it cannot reconcile spend across a session. Wire the measured half
to the ledger once OS#96 lands.

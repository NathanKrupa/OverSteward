# PR Workflow

**All changes flow through PRs. PRs are the project's task board.**

- **Scope first.** Before writing code, state: (a) branch name, (b) PR title, (c) 1-3 bullet scope. If unclear, scope isn't ready
- **One PR = one logical change.** If implementation outgrows description, stop and split
- **Plan before code for anything past a one-function change, and size each PR to clear review in one round.** Architect plan → red-team → rebuild comes before the first line, not after the first `BLOCK`. Round 1 reads the whole diff and costs what the diff costs: 68 minutes on GS#2800, whose design moved three times under review, against 6–14 for each delta round. A change that `make verify` forces you to narrow, or that has to be re-scoped between rounds, was under-designed — and review is the most expensive place for that to surface
- **Never commit directly to main/master.** Branch protection enforces this
- **Never use `--admin` to bypass CI.** Wait for checks
- **Draft PRs for exploration.** Convert to ready when scope is clear
- **Run the adversarial reviewer between "tests green" and `gh pr create`**, and paste its verdict block into the PR body. Your `*-dev` agent card carries the exact commands; `shared/agents/adversarial-reviewer.md` is the brief. A `BLOCK` means do not open the PR
- **Before round 1, run the reviewer's own catalogue yourself and paste the table.** For every destructive statement in the diff (DELETE, UPDATE, upsert), list each `WHERE` conjunct, each element of the natural key, both edges of any window, and every state a row can be in at an insert's key — one negative fixture per line, and the mutant that kills it. Half of GS#2540's eleven rounds were this table, found one row per round
- **Before round 1, check every claim your comments make.** Each invariant a docstring or comment in the diff asserts — "tops out at 3", "rows are never deleted", "a snapshot hit is unconditionally a success" — is verified against the code or data it names (grep it, measure it, read the function) or rewritten to say it is unverified. This is the pre-review form of *a comment asserting an invariant is part of the security surface* (below), and it covers claims inherited from a plan: a plan is a hypothesis about the code, not a reading of it. Three of GS#2800's five round-1 findings were claims the code did not keep; on GS#2797 the same check caught a false score ceiling, taken on trust from the architect, whose test would have passed a pin that loses
- **The loop is three rounds, on a count the assembler keeps.** It writes `.review-rounds` beside its output and derives the round from it, so omitting a flag cannot restart the count; every assembly that produced a document counts, measured or not, and only a refusal leaves the ledger untouched. There is no restart flag: a genuinely new change gets a new worktree, and the PR body, which carries every round's verdict (the final one in the single ```reviewer-verdict fence the CI gate reads, earlier rounds as plain text beneath it), is where a count that began again shows. Round 1 reads the whole change. A `BLOCK` gets one re-review **on the delta** (`--since <reviewed sha> --previous-verdict <file with the verdict block, verbatim>`; the file must parse as a `BLOCK` verdict), which verifies the fixes and does not re-derive round 1. `PASS-WITH-FINDINGS` gets **no re-review**: fix, record each fix's red mutant in the PR body, merge. A fourth round is refused without `--override-cap '<reason>'`; a third `BLOCK` goes to Nathan as issues plus `needs-input`. Record the harness's token count for each round beside the reviewer's self-report
- **Never edit the branch while a review runs.** A verdict certifies the SHA the assembler read, not the branch. Queue every fix until the verdict lands, then re-assemble on the delta. GS#2800's round 1 was assembled against a commit that two narrowing commits had replaced by the time it reported; the reviewer noticed and re-verified against the tip, which is luck, not a control. A verdict whose SHA is not the PR head is not a verdict for the PR (tooling to enforce it: OS#534)
- **Write a trajectory note before opening the PR**, at `<repo>/documentation/trajectories/YYYY-MM-DD-PR<N>.md`. Use the schema in OverSteward `documentation/trajectories/TEMPLATE.md`
- **Branch naming:** `feat/short-description`, `fix/short-description`, `docs/short-description`
- **Merge with `gh pr merge --merge` (or `--auto --merge`), never `--delete-branch`.** Every dispatch-target repo and OverSteward has `delete_branch_on_merge` on (verified by hand 2026-09-18; OS#510 makes `sync-status` measure it): GitHub deletes the head branch on merge and **retargets** any open child PR onto the merged PR's base (measured, OS#508/#509). The flag is a no-op under `--auto` and an unmeasured refs-API delete otherwise; a refs-API delete of a branch an open PR bases on, with no merged PR behind it, **closes** that PR (measured) — so the deletion is left to the setting
- **Cleanup after `MERGED` is standing-authorized, never an operator step.** Confirm with `gh` that the PR is `MERGED`, then `worktree_doctor.py teardown` the worktree (and its `.baseline` sibling), `sweep`, `git branch -d` the local branch, and — only if the remote ref survived, and only after `gh pr list --base <branch> --state open` prints nothing — `gh api -X DELETE repos/<owner>/<repo>/git/refs/heads/<branch>`. `-d` checks the upstream tracking ref, not the trunk — the PR state is the merged-check, and `-D` is never the answer. The doctor's refusal is the one legitimate stop, and it is fixed in-session, not handed over. **A stack is cleaned up by its last PR to merge**: a child's cleanup re-runs the sequence for each ancestor. The dispatch playbook does this itself for a run that finishes; the sequence with its existence tests is OverSteward `.claude/skills/dispatch/SKILL.md` §5
- `gh pr list` replaces checking todo files for project status

## Inert controls

A control the passing state shares with the forgotten state is not a control.
Each rule below states its mechanism; the incidents behind them are in the
trajectory corpus, not here.

- **A guard that can be satisfied by doing nothing is inert.** Fail closed, and force a recorded decision *in the same diff*. If "handled correctly" and "never noticed" produce the same output, the guard is decoration
- **A prohibition is inert while the same document still prescribes the forbidden form.** Before calling a doctrine fix complete, `grep` the *whole* document — and every deployed byte-copy of it — for the form you just forbade
- **A merged watchdog is not a live watchdog.** Detection code, its host install (the timer / cron / hook that actually runs it), and the instrumentation the probe reads are three separate deliveries. Before calling a supervisor deployed, verify all three: the code is merged, the host runs it on schedule, and a forced failure visibly alerts
- **A comment asserting an invariant is part of the security surface.** Prose declaring an exemption safe suppresses the scrutiny that would catch its violation. Either the claim is enforced by a test or a guard, or the comment must say it is *unverified*. Touching code whose safety comment you rely on obliges you to re-verify the claim, not cite it
- **A regression test that was never seen red is not a regression test.** Before the fix lands, run **each new test individually** against the unfixed code and watch it fail for the stated reason. A test red only because its import does not exist yet proves the *module* is new, not that the guard bites — an ImportError red must not be reported as seen-red on its own. After the implementation exists, **mutate it** (invert the guard, move the check after the call, delete the filter) and re-run each new test: the ones that stay green are pins or decoration, and must be rewritten or declared as invariant pins in the PR body. **A survivor indicts the mutant before the test.** Before ruling a green test vacuous, prove the mutated line is on the test's path: an earlier guard may short-circuit before it, a stub may replace the whole layer you mutated, and a mutant checked against the one test you expected to redden misses the sibling that carries the guard — mutate by file. Six trajectory notes across three repos (OS#432, OS#456, AG#1849, AG#1867, GS#2516, GS#2666) report a "vacuous test" that was a bad mutant, and twice the survivor was a real bug the suite could not see. Never weaken the mutant to make it bite. The adversarial reviewer performs this mutation pass independently; your own is still owed

## False greens — a check that reports success must prove it can fail

A green is a *measurement*, and a measurement is only worth its sensitivity.
These rules make that sensitivity demonstrable.

- **A new check ships with the fixture that makes it fail.** Green against live data measures the data, not the check. The proof is the negative fixture: make the check red on purpose, watch it fail for the stated reason, and cite that fixture in the PR. **A canary must assert it can alert on every run**, because silence is its failure mode
- **Never pipe a gate through `| tail` or `| head`.** The pipeline's exit status is the *last* command's, so a failing gate reads as a pass. Redirect to a file and read it — `cmd > /tmp/out 2>&1; rc=$?` — or check `${PIPESTATUS[0]}`. The prohibition covers any filter in the final position. `guard_gate_pipe.py` refuses the shape at the Bash tool; it sees only Claude Code, so a Makefile, a terminal or a CI runner still needs the rule
- **A uniform result is a suspect result.** When a sweep reports the same verdict for every subject, prove it visited distinct subjects before believing it
- **Read the rows a PR's evidence rests on, not the rate.** A dry run's agreement score, a sample's pass count, or "N of N" is a measurement only after its rows have been read. GS#2797's dry run reported 20/20 agreement between the crawl request and the identity selector, and four of the twenty were email addresses that both functions turned into `gmail.com` — consistent and meaningless. GS#2791 was filed on "2,577 of 2,577 excerpts empty", which came from `dict.get` on a misspelled key: a measurement that could not return anything else
- **`rc=0` is not a pass on its own.** Some tools exit 0 on usage errors, and some ignore the severities you asked them to gate on. For any tool not *known* to fail loudly, assert on the output as well as the code
- **A skip must not read as a pass.** "Found nothing" and "could not look" must never print or exit the same. Give the two outcomes different exit codes — 2 for "could not look", as `worktree_doctor.py sweep`, `gaudi_check_files.py`, `check_hooks_path.py` and `sync_repos.py` do
- **A gate that applies a fix must assert the fixed bytes are the ones being certified.** A formatter or generated file rewritten *during* verify leaves the rewrite unstaged, so the marker is written at HEAD and the push ships unformatted bytes. Assert the tracked tree equals HEAD and fail *before* any marker is written; `require_formatted_commit.py` and `format_staged.py` are the sanctioned members
- **A linter's exit code is a claim about the severity tier it was asked to gate, so name the tier and prove it.** The estate gates gaudi on the error tier by policy, because the warn tier is too noisy to enforce, not because a warn-tier gate could never fire. State which tier gates, and prove it with a finding of that tier — a report that prints warnings under an error-tier gate is reviewer input, not a control
- **When two implementations of a control produce identical output on the chosen fixture, the fixture is wrong, not the control.** Pick the input where the orderings diverge — the row the old code drops and the new code keeps, the boundary the filter is meant to cut — and assert on that. A fixture on which the mutant and the fix agree proves nothing about either
- **A restore that re-enters a capture context is not a restore.** A fixture, env or monkeypatch teardown that restores to a value the *run itself* authored (a state captured after setup, a snapshot taken inside the patched region) re-authors the fault it was meant to undo. Restore to a name declared *outside* the run — the value at module import, the committed file, the origin ref
- **A gate run in a worktree certifies whichever tree Python imports — prove it is the worktree.** The shared `.venv`'s editable `.pth` points at the primary checkout, so without an **absolute** `PYTHONPATH=<worktree>/src` every gate silently measures the primary tree. Before the first gate and after any `cd`, print the resolved path and read it: `.venv/bin/python -c "import <pkg>; print(<pkg>.__file__)"`. A repo whose cross-repo siblings are MetaPathFinder installs (aigranthelper) must reinstall them into the worktree's own venv instead — `PYTHONPATH` cannot shadow those
